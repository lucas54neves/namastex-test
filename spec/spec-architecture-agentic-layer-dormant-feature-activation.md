# Introduction

Three features of the agentic layer are fully implemented in Python but are effectively unreachable at runtime due to one state-management bug and two configuration gaps. This specification defines the corrections required to activate quality drift detection (GAP-A05), the targeted-tests promotion gate (QUAL-01), and LLM self-review auto-approval — without changing any public interface or data contract.

## 1. Purpose & Scope

**Purpose:** Define the minimal corrections that activate three dormant agentic features so that every cycle of the pipeline exercises the complete governance path as intended by the architecture.

**Scope:** Three targeted changes across three files:

| ID | Kind | File | Feature unlocked |
|---|---|---|---|
| FIX-A | Bug | `src/pipeline/orchestration/operator.py` | Quality drift detection (GAP-A05) |
| FIX-B | Config | `config/pipeline_spec.json` | Targeted-tests gate (QUAL-01) |
| FIX-C | Config | `config/agent_autonomy_policy.json` | LLM self-review auto-approval |

**Out of scope:** Changes to data schemas, transformation logic, test suites, or any other module not listed above. The public interfaces of `run_cycle()`, `evaluate_candidate()`, and `classify_proposal()` must not change.

**Intended audience:** Engineers implementing the corrections and reviewers of the resulting PR.

## 2. Definitions

| Term | Definition |
|---|---|
| `quality_baseline` | Snapshot of Bronze null-rates, record count, and category distributions saved to `state/pipeline_state.json` by `plan_pipeline_spec()`, used by the quality drift detector on subsequent cycles |
| `targeted_tests` gate | Gate inside `evaluate_candidate()` (`autonomy.py`) that executes a pytest subset via `subprocess.run` before promoting a candidate spec; result field in `gate_results["targeted_tests"]` |
| `agent_auto_approve_if_confidence_ge` | Per-family float threshold in `agent_autonomy_policy.json`; when present and the LLM self-review confidence meets or exceeds it, `agent_self_review_proposal()` approves the proposal without human intervention |
| `data_quality_drift` family | Proposal family generated by the quality drift detector; requires its own entry in `mutation_families` of the autonomy policy |
| `plan_pipeline_spec()` | Function in `planner.py` called inside `run_cycle()` when source has changed, is forced, or cadence triggers; saves `quality_baseline` to the state file as a side effect |
| `run_cycle()` | Main orchestration function in `operator.py`; loads state at entry, calls `plan_pipeline_spec()`, then saves state at multiple exit points |
| `DEFAULT_AUTONOMY_POLICY` | In-code constant in `autonomy.py` (lines 38–100) that defines all expected fields for the policy; used as the source of truth for FIX-C |
| `compiled_plan` | Result of `compile_pipeline_spec(spec)` — a flat dict derived from `pipeline_spec.json`; the `agent` sub-dict is used by `_run_targeted_tests_gate()` to read `targeted_test_paths` |

## 3. Requirements, Constraints & Guidelines

### FIX-A — Quality baseline preserved after `plan_pipeline_spec()` call

- **REQ-A01**: After `plan_pipeline_spec(paths)` returns at `operator.py:156`, `run_cycle()` MUST reload the pipeline state from disk before any subsequent call to `save_pipeline_state()`. This ensures that `quality_baseline` written by `plan_pipeline_spec()` is not overwritten by the stale in-memory dict loaded at line 139.
- **REQ-A02**: The reload MUST be placed immediately after the `plan_pipeline_spec(paths)` call, unconditionally — regardless of whether the execution path is the early-exit (line 242) or the main run path (lines 683, 783).
- **REQ-A03**: The reloaded state MUST be assigned to the same `state` variable used by all subsequent operations in `run_cycle()`, so that the runs list, fingerprints, and timestamps appended later are accumulated on top of the baseline-enriched dict.
- **CON-A01**: The interface of `run_cycle()` MUST NOT change (same signature, same return type).
- **CON-A02**: `plan_pipeline_spec()` MUST NOT be modified; it already saves `quality_baseline` correctly.
- **CON-A03**: The fix MUST NOT add an extra disk read when `plan_pipeline_spec()` is skipped (i.e., `should_plan` is `False`). The reload MUST be inside the `if should_plan:` block, after `planner_report = plan_pipeline_spec(paths)`.
- **GUD-A01**: The reload is a single line: `state = load_pipeline_state(state_path)` placed immediately after `planner_report = plan_pipeline_spec(paths)` at `operator.py:156`.

### FIX-B — `targeted_test_paths` wired in `pipeline_spec.json`

- **REQ-B01**: The `agent` block in `config/pipeline_spec.json` MUST include the key `"targeted_test_paths"` with value `["tests/test_jobs.py"]`.
- **REQ-B02**: The `agent` block MUST include the key `"targeted_tests_timeout_sec"` with integer value `120`.
- **REQ-B03**: These keys MUST be top-level within the existing `agent` object, alongside `safe_auto_apply_playbooks` and `planner`.
- **CON-B01**: No other key in `pipeline_spec.json` may be modified by this fix.
- **CON-B02**: `tests/test_jobs.py` is the only test file to add; it is already executed in CI and its runtime fits within 120 seconds.
- **CON-B03**: The `_run_targeted_tests_gate()` function in `autonomy.py` reads these values via `compiled_plan["agent"].get("targeted_test_paths", [])` and `compiled_plan["agent"].get("targeted_tests_timeout_sec", 120)`. No code changes are required — only the JSON configuration.
- **GUD-B01**: The gate skips execution for `validation_enhancement` proposals with `impact_class="low"` (CON-102 of QUAL-01 spec); FIX-B does not change that behavior.

### FIX-C — `agent_autonomy_policy.json` synchronized with `DEFAULT_AUTONOMY_POLICY`

- **REQ-C01**: `config/agent_autonomy_policy.json` MUST include the field `"agent_auto_approve_if_confidence_ge"` for each mutation family that has it defined in `DEFAULT_AUTONOMY_POLICY` in `autonomy.py`. The values are:
  - `"schema_update"`: `0.90`
  - `"segmentation_adjustment"`: `0.90`
  - `"transformation_rule_change"`: `0.85`
  - `"data_quality_drift"`: `0.85`
- **REQ-C02**: `config/agent_autonomy_policy.json` MUST include a `"data_quality_drift"` entry under `"mutation_families"` with the following fields and values, matching `DEFAULT_AUTONOMY_POLICY`:
  ```json
  "data_quality_drift": {
    "default_impact_class": "high",
    "auto_promote": false,
    "requires_approval": true,
    "requires_backward_compatibility": false,
    "requires_privacy_scan": false,
    "agent_auto_approve_if_confidence_ge": 0.85
  }
  ```
- **REQ-C03**: Existing mutation families in the JSON file (`schema_update`, `validation_enhancement`, `derived_column_addition`, `segmentation_adjustment`, `transformation_rule_change`) MUST be updated to add the `"agent_auto_approve_if_confidence_ge"` field where applicable (REQ-C01), without modifying any other existing field.
- **CON-C01**: The `validation_enhancement` and `derived_column_addition` families do NOT receive `agent_auto_approve_if_confidence_ge` because they are already `auto_promote: true` and `requires_approval: false` — the self-review path is never reached for them.
- **CON-C02**: `load_autonomy_policy()` in `autonomy.py` uses the JSON file content directly when the file exists; it does NOT merge per-key with `DEFAULT_AUTONOMY_POLICY`. Therefore the JSON file must be complete for all fields that the code reads.
- **CON-C03**: No code in `autonomy.py` or any other module may be changed by FIX-C.
- **GUD-C01**: After FIX-C, `get_agent_auto_approve_threshold(paths, "schema_update")` MUST return `0.90` and `get_agent_auto_approve_threshold(paths, "data_quality_drift")` MUST return `0.85`.

## 5. Acceptance Criteria

### FIX-A

- **AC-A01**: Given a forced run (`--force`), when `run_cycle()` completes, then `state/pipeline_state.json` MUST contain the key `quality_baseline` with a non-null dict at the top level.
- **AC-A02**: Given `quality_baseline` present in `pipeline_state.json` and a subsequent cycle where Bronze null-rate drift exceeds the configured threshold, when `plan_pipeline_spec()` runs, then the quality drift detector MUST generate at least one `data_quality_drift` proposal.
- **AC-A03**: Given a cycle where `should_plan` is `False` (no source change, no cadence trigger, no force), when `run_cycle()` completes, then `state/pipeline_state.json` MUST preserve the `quality_baseline` key that was written by the previous cycle.
- **AC-A04**: The reload of `state` MUST NOT happen when `should_plan` is `False` (no extra disk read on idle cycles).

### FIX-B

- **AC-B01**: Given a candidate proposal that modifies `gold.required_columns`, when `evaluate_candidate()` runs after FIX-B, then `gate_results["targeted_tests"]["executed"]` MUST be `True`.
- **AC-B02**: Given `tests/test_jobs.py` passes (returncode 0), then `gate_results["targeted_tests"]["passed"]` MUST be `True` and `gate_results["targeted_tests"]["returncode"]` MUST be `0`.
- **AC-B03**: Given a proposal with `proposal_family="validation_enhancement"` and `impact_class="low"`, when `evaluate_candidate()` runs, then `gate_results["targeted_tests"]["executed"]` MUST be `False` with `reason="low_impact_validation_enhancement_skipped"` (existing skip rule preserved).
- **AC-B04**: The file `runtime/candidates/<proposal_id>/candidate_test_report.json` MUST contain the `targeted_tests` result matching the schema in section 4.5 after any candidate evaluation.

### FIX-C

- **AC-C01**: Given `agent_autonomy_policy.json` updated per FIX-C, when `get_agent_auto_approve_threshold(paths, "schema_update")` is called, then it MUST return `0.90`.
- **AC-C02**: Given `get_agent_auto_approve_threshold(paths, "data_quality_drift")`, it MUST return `0.85`.
- **AC-C03**: Given `get_agent_auto_approve_threshold(paths, "validation_enhancement")`, it MUST return `None` (family has no threshold — auto_promote is already true).
- **AC-C04**: Given a `schema_update` proposal whose gate results all pass and whose LLM self-review returns `should_approve=True` with `confidence=0.92`, when `plan_pipeline_spec()` processes it, then `approve_proposal()` MUST be called with approver `"agent"` and the proposal status MUST advance past `awaiting_approval`.
- **AC-C05**: Given a `data_quality_drift` proposal, when `classify_proposal("data_quality_drift", paths)` is called, then it MUST return `impact_class="high"`, `safe_auto_promote=False`, `requires_approval=True`.

## 7. Rationale & Context

### FIX-A — Why the bug exists

`run_cycle()` loads `state` at its entry point (line 139 of `operator.py`). `plan_pipeline_spec()` is called at line 156 and, as a side effect, loads and saves the state file with `quality_baseline` appended. However, the local `state` variable in `run_cycle()` is never refreshed after this call. All three subsequent `save_pipeline_state()` calls at lines 242, 683, and 783 use the stale dict, which does not contain `quality_baseline`. The last write wins, and `quality_baseline` is permanently lost until the next planner run — which immediately overwrites it again. The net effect is that `quality_baseline` is never present in the file when `load_quality_baseline()` is called at the start of the next `plan_pipeline_spec()`, so `_quality_drift_proposals()` always returns an empty list (it short-circuits on `if baseline is None`).

### FIX-B — Why the gate is a no-op

`_run_targeted_tests_gate()` reads `targeted_test_paths` from `compiled_plan["agent"]`. `compile_pipeline_spec()` derives `compiled_plan` from `pipeline_spec.json`. The `agent` block in `pipeline_spec.json` has never included `targeted_test_paths`. The gate function has a correct short-circuit: `if not test_paths: return {..., "executed": False, "reason": "no_targeted_tests_configured"}`. The gate was implemented and tested in isolation (QUAL-01) but the configuration bridge was never added.

### FIX-C — Why auto-approval is silent

`get_agent_auto_approve_threshold()` performs `policy.get("mutation_families", {}).get(proposal_family, {}).get("agent_auto_approve_if_confidence_ge")`. The `DEFAULT_AUTONOMY_POLICY` constant in `autonomy.py` has these thresholds, but `load_autonomy_policy()` only uses `DEFAULT_AUTONOMY_POLICY` as the `default` argument to `read_json()` — meaning it is applied only when the file does not exist. The JSON file was created early in the project from a partial template that predates the introduction of `agent_auto_approve_if_confidence_ge`. Because the file exists, `read_json()` returns it as-is, never merging with the defaults. The result is that the threshold lookup always returns `None`, the `if threshold is not None:` guard in `plan_pipeline_spec()` is never entered, and `agent_self_review_proposal()` is never called.

## 8. Dependencies & External Integrations

### Infrastructure Dependencies

- **INF-001**: `state/pipeline_state.json` — mutable runtime file; must survive the reload introduced by FIX-A without data loss.
- **INF-002**: `config/pipeline_spec.json` — versioned configuration file; FIX-B adds two keys to the `agent` block and the file is promoted through the existing spec-history mechanism on the next planner cycle.
- **INF-003**: `config/agent_autonomy_policy.json` — versioned policy file; FIX-C updates five families and adds one. The file is read on every `classify_proposal()` call.
- **INF-004**: `venv/bin/python` — required by `_run_targeted_tests_gate()` (FIX-B) to invoke pytest in a subprocess. Must be present in the environment where `run_cycle()` executes, including Databricks (where the venv layout is reproduced via the job environment).

### Technology Platform Dependencies

- **PLT-001**: Python 3.11+ — no change; all three fixes use only stdlib and already-imported modules.

### Compliance Dependencies

- **COM-001**: FIX-A preserves all existing PII and publication-policy behaviors; `quality_baseline` contains only aggregate statistics (null rates, record counts, category distributions) with no row-level data.

## 9. Examples & Edge Cases

### FIX-A — Edge case: planner skipped on idle cycle

When `should_plan` is `False`, the reload must NOT happen:

```python
# operator.py — correct flow for idle cycle
if should_plan:
    planner_report = plan_pipeline_spec(paths)
    state = load_pipeline_state(state_path)  # reload only here
else:
    planner_report = _EMPTY_PLANNER_REPORT
# No reload here — state still holds the dict loaded at line 139
```

In this scenario `quality_baseline` was written by a previous cycle and is already in the state file. The idle-path save at line 242 reloads and re-saves the dict that was loaded at line 139, which already contains `quality_baseline` from the last planner run — because AC-A03 requires the key to survive idle cycles. This is consistent only if the very first planner run correctly preserved the key, which is guaranteed by FIX-A.

### FIX-B — Edge case: candidate with no schema diff

A `validation_enhancement` proposal (adds a new validation rule but does not add or remove items from `required_columns`) produces no `schema_diff`. The gate evaluates:

```python
required_col_changed = False   # no diff in required_columns
validation_rules_changed = True  # quality.validation_rules changed
```

Because `validation_rules_changed` is `True`, the gate DOES execute tests. The `validation_enhancement`/`low` skip (CON-B01) would have already returned before this point for proposals that are `impact_class="low"`. A `validation_enhancement` that reaches the schema-diff check is medium or high impact, so tests run.

### FIX-C — Edge case: threshold exactly at boundary

If `confidence = 0.90` and `threshold = 0.90` for `schema_update`, the condition `float(review["confidence"]) >= threshold` evaluates to `True` (inclusive). The proposal is approved. This matches the semantics of the Python `>=` operator as specified in `plan_pipeline_spec()`.

### FIX-C — Edge case: `data_quality_drift` proposal approval path

A `data_quality_drift` proposal with all gates passing and LLM returning `confidence=0.87`:

```
threshold = get_agent_auto_approve_threshold(paths, "data_quality_drift")  # → 0.85
review = agent_self_review_proposal(...)  # → {"should_approve": True, "confidence": 0.87}
0.87 >= 0.85  # True → approve_proposal called → status advances
```

Without FIX-C, `threshold` returns `None`, the `if threshold is not None:` guard is skipped, and the proposal remains `awaiting_approval`.

## 10. Validation Criteria

- **VAL-001**: After applying FIX-A and running `venv/bin/python scripts/run_pipeline.py --force`, `state/pipeline_state.json` MUST contain the key `"quality_baseline"` at the top level with a non-null dict value.
- **VAL-002**: On a second run without `--force` (no source change), `state/pipeline_state.json` MUST still contain `"quality_baseline"` — it must not have been overwritten to null or removed.
- **VAL-003**: After applying FIX-B and running `venv/bin/python scripts/plan_pipeline.py`, if any candidate was evaluated with a schema diff, `runtime/candidates/<id>/candidate_test_report.json` MUST contain `"executed": true`.
- **VAL-004**: After applying FIX-C, `python -c "from pipeline.config import PipelinePaths; from pipeline.agent.autonomy import get_agent_auto_approve_threshold; p = PipelinePaths.from_env(); print(get_agent_auto_approve_threshold(p, 'schema_update'))"` MUST print `0.9`.
- **VAL-005**: `venv/bin/python -m pytest -q` MUST pass with zero failures after all three fixes are applied.
- **VAL-006**: `grep "quality_baseline" state/pipeline_state.json` MUST return a match after a forced run.
- **VAL-007**: `grep "targeted_test_paths" config/pipeline_spec.json` MUST return a match after FIX-B.
- **VAL-008**: `grep "agent_auto_approve_if_confidence_ge" config/agent_autonomy_policy.json | wc -l` MUST return `4` (one per applicable family: `schema_update`, `segmentation_adjustment`, `transformation_rule_change`, `data_quality_drift`).
